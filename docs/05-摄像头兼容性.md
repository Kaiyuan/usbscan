# 05 · 摄像头兼容性

> 文档版本：0.3　|　状态：评审中　|　最后更新：2026-11-07
>
> 本项目最大的技术风险集中在本章。任何"某摄像头用不了"的问题都应先查本文。

---

## 1. 目标

**任何一台能在 Windows 10/11 上被系统识别的 USB 摄像头，都必须能在 usbscan 中出图。**

"能用"包含四层含义：

1. 能枚举到；
2. 能打开；
3. 能持续取到帧（≥12fps）；
4. 能在常见异常下自行恢复。

---

## 2. 双后端策略

| 后端 | 角色 | 启用条件 |
|---|---|---|
| **Media Foundation (MF)** | 主路径 | 默认优先 |
| **DirectShow (DShow)** | 兜底 | MF 枚举缺失 / 打开失败 / 无帧 / 黑屏 |

### 2.1 为什么 MF 优先

- 硬件 MJPEG / H.264 解码，1080p30 CPU 占用可低于 5%。
- `MF_SOURCE_READER_ENABLE_ADVANCED_VIDEO_PROCESSING` 请求 `RGB32` 输出时，YUV→RGB 由驱动或 MF 完成。
- 原生支持共享模式（多程序同时打开）。
- 与 D3D11 纹理互操作，避免二次拷贝。

### 2.2 为什么仍要 DShow

- 部分国产 UVC 模组的 MF 驱动实现不完整（无格式枚举、打开即失败）。
- 某些采集卡只提供 WDM 流接口。
- 部分虚拟摄像头只在 DShow 注册。
- 老设备（2010 年前）多为 WDM/DShow 时代产物。

### 2.3 合并策略

```
MF 枚举结果 ─┐
             ├─▶ 按符号链接归并 ─▶ 统一设备列表
DShow 枚举 ──┘
```

- 主键：`MF_DEVSOURCE_ATTRIBUTE_SOURCE_TYPE_VIDCAP_SYMBOLIC_LINK` 与 DShow `DevicePath`（两者格式一致）。
- 归并后记录：`backends = MF | DSHOW`。
- 界面只显示一条；打开时按 `MF → DShow` 顺序尝试，失败自动降级并在状态栏提示"已切换到兼容模式"。

## 3. 设备枚举

### 3.1 Media Foundation

```
MFStartup(MF_VERSION, MFSTARTUP_FULL)
MFEnumDeviceSources(MF_DEVSOURCE_ATTRIBUTE_SOURCE_TYPE_VIDCAP_GUID, &devices)
  ├─ MF_DEVSOURCE_ATTRIBUTE_FRIENDLY_NAME        → 显示名
  ├─ MF_DEVSOURCE_ATTRIBUTE_SOURCE_TYPE_VIDCAP_SYMBOLIC_LINK → 稳定 ID
  └─ 由符号链接解析 VID/PID（可选，用于展示与排错）
```

注意：

- 必须 `CoInitializeEx` 于采集线程。
- 每个 `IMFActivate` 使用后必须 `ShutdownObject`，否则设备被"占用"。
- 枚举本身会激活设备一瞬间，某些摄像头会闪灯，属正常。

### 3.2 DirectShow

```
CoCreateInstance(CLSID_SystemDeviceEnum) → ICreateDevEnum
CreateClassEnumerator(CLSID_VideoInputDeviceCategory)
  遍历 IMoniker → BindToStorage(IPropertyBag)
  ├─ "FriendlyName" → 显示名
  └─ "DevicePath"   → 稳定 ID
```

### 3.3 虚拟摄像头识别

判定为虚拟设备的启发式：

| 特征 | 说明 |
|---|---|
| 名称含 `Virtual` / `OBS` / `iVCam` / `Snap Camera` / `ManyCam` | 名称匹配 |
| 符号链接不含 `usb#vid_` | 非 USB 物理设备 |
| 无任何 `IAMVideoProcAmp` 支持 | 无硬件控制项 |

默认隐藏，设置中可开启"显示虚拟摄像头"。

## 4. 格式枚举与协商

### 4.1 枚举

MF：`IMFSourceReader::GetNativeMediaType(stream, index)` 遍历，取：

- `MF_MT_FRAME_SIZE`
- `MF_MT_FRAME_RATE` / `MF_MT_FRAME_RATE_RANGE`
- `MF_MT_SUBTYPE`（`MFVideoFormat_MJPG` / `NV12` / `YUY2` / `RGB32` / `H264`）
- `MF_MT_INTERLACE_MODE`（隔行设备需去隔行，概率极低但需容错）

DShow：`IAMStreamConfig::GetStreamCaps` 遍历。

去重后按 `(分辨率降序, 帧率降序)` 排序；同分辨率同帧率只保留最优像素格式。

### 4.2 评分算法

```
score = 0.50 * norm(width * height)
      + 0.30 * norm(fps)
      + 0.20 * format_score

format_score:
  NV12 / RGB32 : 1.00   (免转换)
  MJPG         : 0.90   (需解码，但带宽友好)
  YUY2         : 0.70   (带宽杀手)
  H264         : 0.50   (主要是录制用)

过滤: fps < 12 的条目不进"推荐"，但仍可在列表中手动选择
默认: 得分最高者；若用户为该设备保存过选择，则用保存值
```

### 4.3 用户切换时的联动

选择分辨率 → 过滤可用像素格式 → 过滤可用帧率。若用户选中的组合不可用，回退到该分辨率下最高帧率并提示。

### 4.4 USB 带宽预算

| 分辨率@帧率 | YUY2 | MJPG(质量 85) | 结论 |
|---|---|---|---|
| 640×480@30 | ~147 Mbps | ~20 Mbps | 都可行 |
| 1280×720@30 | ~442 Mbps | ~45 Mbps | YUY2 接近 USB2 上限 |
| 1920×1080@30 | ~995 Mbps | ~90 Mbps | **YUY2 基本不可用** |
| 2560×1440@30 | 超限 | ~150 Mbps | 仅 MJPG |
| 3840×2160@30 | 超限 | ~330 Mbps | 仅 MJPG + USB3 |

检测到 `MF_E_UNSUPPORTED_BYTESTREAM_TYPE` / `VFW_E_NOT_ENOUGH_BANDWIDTH` 时：

1. 降一档分辨率；
2. 若仍失败，切 MJPG；
3. 仍失败，提示"该 USB 端口带宽不足，请换用 USB 3.0 接口或降低分辨率"。

## 5. 打开与启动流程

```
1. 打开设备 (MF: MFCreateDeviceSource / DShow: FilterGraph)
2. 设置格式
3. 设置缓冲区（MF: MF_SOURCE_READER_ENABLE_ADVANCED_VIDEO_PROCESSING）
4. 启动流
5. 等待首帧（超时 3 秒）
   ├─ 收到帧 → 进入预览
   └─ 超时   → 尝试下一个格式；仍失败 → 切后端
6. 校验首帧健康度（全黑/全绿/全白检测）
   └─ 异常 → 记录并提示"画面异常，可能为驱动问题"
```

### 5.1 首帧健康检查

| 检查 | 判定 | 处理 |
|---|---|---|
| 全黑（>99% 像素 Y<16） | 可能是镜头盖或驱动问题 | 提示但继续，不阻塞 |
| 全单一色 | 驱动未输出 | 切后端重试 |
| 尺寸与协商值不符 | 驱动谎报 | 以实际尺寸为准，更新 UI |
| 帧率 < 1fps | 驱动卡死 | 关闭重开一次 |

## 6. 异常处理表

| 现象 | 错误码 | 检测 | 处理 | 用户可见提示 |
|---|---|---|---|---|
| 被其他程序独占 | E1001 | `MF_E_SHARE_MODE_DENIED` / `VFW_E_IN_USE` | 枚举占用进程 | "摄像头正被 Teams.exe 占用" + 关闭按钮 |
| 设备不存在 | E1002 | `MF_E_DEVICE_REMOVED` | 刷新列表 | "设备已断开" |
| 无可用格式 | E1003 | native type 为空 | 切后端重试 | "该设备未提供视频格式" |
| 打开失败 | E1004 | HRESULT 失败 | 切后端重试 | "无法打开摄像头" + 原因 |
| 3 秒无帧 | E1005 | 超时 | 换格式 → 换后端 → 重开 | "摄像头无画面输出" |
| 带宽不足 | E1006 | `VFW_E_NOT_ENOUGH_BANDWIDTH` | 降档 | "USB 带宽不足" |
| 中途断流 | E1007 | 连续 2 秒无新帧 | 自动重开（3 次退避） | 静默恢复，状态栏提示 |
| 设备拔出 | E1008 | `WM_DEVICECHANGE` | 停止流、保留会话 | "设备已拔出，等待重新连接" |
| 驱动崩溃 | E1009 | 进程内异常 / 无法重开 | 提示重启软件 | "摄像头驱动异常" |
| 画面全绿 | E1010 | 健康检查 | 切后端 | "画面异常，已切换兼容模式" |
| 帧率极低 | E1011 | 实测 <5fps | 提示 | "当前格式帧率过低，建议改用 MJPG" |

### 6.1 重连状态机

```
   ┌──────────┐  失败<3次   ┌──────────┐
   │ Running  │ ──────────▶ │ Recover  │
   └────┬─────┘             └────┬─────┘
        │ 拔插                   │ 成功
        ▼                        ▼
   ┌──────────┐             ┌──────────┐
   │ Detached │ ──────────▶ │ Running  │
   └──────────┘   重新插入    └──────────┘
        │ 30 秒未插回
        ▼
   ┌──────────┐
   │  Idle    │  (显示引导界面)
   └──────────┘
```

退避间隔：200ms → 800ms → 2000ms，最多 3 次。

## 7. 摄像头控制

### 7.1 通用控制项

通过 DShow 接口（对同一物理设备，MF 后端也可通过拓扑节点获取 `IKsControl`，但实现复杂，v1 统一用 DShow 打开一个轻量图来读控制项）：

| 接口 | 控制项 |
|---|---|
| `IAMVideoProcAmp` | 亮度、对比度、色相、饱和度、锐度、伽马、白平衡、背光补偿、增益 |
| `IAMCameraControl` | 曝光、对焦、变焦、光圈、全景、倾斜、滚动 |

每项通过 `GetRange()` 返回 `(min, max, step, default, caps)`：

- `caps` 不含 `KSPROPERTY_SUPPORT_GET` → 隐藏该项。
- `caps` 含 `AUTO` → 显示"自动"复选框。

### 7.2 呈现规则

- **只显示受支持的项**，不显示灰化项（普通网络摄像头通常只有亮度/对比度/曝光）。
- 参数按设备符号链接持久化，换设备不串味。
- 拖动滑块采用 30ms 尾沿防抖，避免刷爆驱动。

### 7.3 系统属性页

"高级…"按钮通过 `ISpecifyPropertyPages` + `OleCreatePropertyFrame` 打开系统自带的 DirectShow 属性页。厂商私有参数（补光、畸变校正、HDR）由厂商自行提供，我们零维护。

> 优势：把"支持所有摄像头的高级设置"这个无底洞，直接甩给驱动厂商的 UI。

## 8. 虚拟摄像头与特殊设备

| 类型 | 处理 |
|---|---|
| OBS Virtual Camera | 可正常采集；无硬件控制项 |
| iVCam / DroidCam | 通过虚拟设备接入；延迟较高，需提示 |
| 采集卡（HDMI→UVC） | 可能有 H.264 输出；主要用于录制 |
| 深度相机（RealSense 等） | 只取彩色流；深度流忽略 |
| 360 相机 | 按普通视频流处理，不做事后展开 |
| 红外摄像头 | 灰度输出，正常显示 |

### 10.3 自动化

- 采集层用 mock 后端（模拟 6 种异常）做集成测试。
- 句柄泄漏检测：每 1000 帧记录 `GetProcessHandleCount`，超过阈值告警。
- 内存泄漏检测：长跑 30 分钟，`PrivateUsage` 增长 < 15%。

## 11. 排错指南（面向用户与支持）

| 症状 | 排查步骤 |
|---|---|
| 列表中无设备 | 设备管理器是否识别 → 是否被其他程序占用 → 是否虚拟摄像头被过滤 |
| 有设备但打不开 | 换 USB 接口 → 关闭其他摄像头程序 → 打开"兼容模式" |
| 有画面但很卡 | 换 MJPG → 降分辨率 → 检查 USB 2.0/3.0 |
| 画面颜色异常 | 打开厂商属性页调整 → 使用手动色彩校正 |
| 拔插后不恢复 | 点击"重置设备" → 重新选择设备 |

诊断包中应包含：设备枚举结果（两后端）、格式列表、实际生效格式、首帧健康检查结果、错误码历史。
