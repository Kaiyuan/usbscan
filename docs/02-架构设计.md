## 1. 总览

```
┌───────────────────────────────────────────────────────────────────────┐
│                           usbscan-app                                │
│                入口 · 装配 · 命令行 · 单实例 · 生命周期                │
└───────────┬───────────────────────────────┬───────────────────────────┘
            │                               │
   ┌────────▼────────┐            ┌─────────▼──────────┐
   │   usbscan-app    │            │   业务服务层        │
   │ Slint 视图/控制器 │            │  capture / doc /   │
   └────────┬────────┘            │  imaging / ocr /   │
            │                     │  naming / export   │
   ┌────────▼────────┐            └─────────┬──────────┘
   │  slint / win32   │                      │
   │ 渲染·采集·系统集成│            ┌─────────▼──────────┐
   └─────────────────┘            │   usbscan-store    │
                                  │ 配置·会话·原子写盘  │
                                  └────────────────────┘
```

依赖方向严格单向：`app(Slint) → 业务 crate → store`，`app → usbscan-win`（录像/配置/主题）。业务 crate 之间不允许循环依赖，共享类型下沉到 `usbscan-coretypes`（或直接由 `usbscan-doc` 提供）。

## 2. 技术选型

### 2.1 选型表

| 关注点 | 选择 | 理由 |
|---|---|---|
| 语言 | Rust stable（edition 2021） | 内存安全、无 GC、零运行时 |
| 窗口/界面 | Slint 1.18（cupertino 风格） | 声明式 UI、圆角卡片与主题切换，开发效率高 |
| 系统集成 | `windows` crate 直接调用 Win32 | 采集、录像、配置、主题检测与文件对话框 |
| 自绘区域 | Slint 软件渲染器 + 像素级叠加 | 实时预览、文档裁剪框与缩略图 |
| 视频呈现 | DXGI Flip Model SwapChain | 低延迟、无撕裂 |
| 采集 | Media Foundation 为主 | 硬件解码、色彩转换、共享模式、低 CPU |
| 采集兜底 | DirectShow | 杂牌驱动、非标格式、MF 异常场景 |
| 解码兜底 | Rust 纯软件（MJPEG/YUY2→RGB） | MF 解码失败时保证有画面 |
| 图像处理 | 自研算子 + `image` 基础编解码 | 算法可控、可调优 |
| OCR | Tesseract 5（静态库） | 唯一离线方案，社区成熟 |
| 条码 | 纯 Rust 解码库 | 无外部依赖 |
| PDF | 纯 Rust 生成 + 字体子集化 | 体积与许可可控 |
| 配置 | TOML + serde | 人类可读、可手改、便于企业部署 |
| 日志 | `tracing` + 自研滚动写入 | 结构化、可附加上下文 |
| 测试 | `cargo test` + `insta`（快照） | 图像算子用快照测试 |

### 2.2 被否决的方案

| 方案 | 否决原因 |
|---|---|
| egui / iced / Druid | 自绘 UI 且样式定制成本高；最终选择 Slint（cupertino 风格） |
| WinUI 3 / Windows App SDK | Rust 绑定不成熟；自带运行时 50–80MB；启动慢；本质仍是 XAML 自绘 |
| Tauri / WebView2 | Web 渲染；Win10 早期版本需额外安装 WebView2 |
| wxWidgets / wxdragon | 用原生控件，但绑定 C++ 库，构建链与包体代价大，深色模式支持差 |
| `native-windows-gui` | 方向正确但维护活跃度一般、DPI/深色支持弱；仅作参考 |
| `nokhwa` / `opencv-videoio` | 均基于 Media Foundation 的薄封装，失去对异常处理的控制 |
| GDI 播放视频 | 无硬件缩放、无 vsync、撕裂明显 |

## 3. 原生 UI 架构

### 3.1 分层

```
usbscan-ui       视图（MainView / SettingsView / OcrView …）
   │             只描述"应该有哪些控件、放在哪、点了做什么"
   ▼
usbscan-win      控件封装（Button / Combo / ListView / Trackbar …）
   │             保留模式：创建 HWND、布局、消息分发、DPI 缩放
   ▼
Win32 / COM      真实系统控件
```

`usbscan-win` 提供最小原语：

```rust
pub trait Control {
    fn hwnd(&self) -> HWND;
    fn layout(&mut self, rect: Rect, dpi: u32);
    fn enabled(&mut self, on: bool);
    fn visible(&mut self, on: bool);
}

pub struct Button { hwnd: HWND, id: u16 }
pub struct ComboBox { hwnd: HWND, id: u16 }
pub struct TrackBar { hwnd: HWND, id: u16 }
pub struct ListView { hwnd: HWND, id: u16, image_list: HIMAGELIST }
pub struct StatusBar { hwnd: HWND }
pub struct Splitter { /* 自绘 4px，但仅绘制一条矩形 */ }
```

### 3.2 窗口层级

```
HWND 主窗口 (WS_OVERLAPPEDWINDOW + HMENU)
├─ ToolbarWindow32
├─ 参数条（原生静态控件 GroupBox 包裹）
├─ Splitter (自绘)
├─ SysListView32 (LVS_ICON | LVS_OWNERDATA)
├─ 预览 HWND (自定义窗口类 "UsbscanPreview")
├─ 属性面板 (GroupBox + Button + TrackBar + ComboBox)
└─ StatusBar (msctls_statusbar32, 4 段)
```

### 3.3 消息路由

| 消息 | 处理 |
|---|---|
| `WM_COMMAND` | 按控件 ID 分发到当前视图的 `on_command` |
| `WM_NOTIFY` | ListView / Toolbar 通知 |
| `WM_HSCROLL` / `WM_VSCROLL` | 滑块变化，带尾沿防抖 |
| `WM_DPICHANGED` | 全量重布局 |
| `WM_THEMECHANGED` | 重建字体与颜色，重绘 |
| `WM_DEVICECHANGE` | 转发到采集服务 |
| `WM_APP_TASK_DONE` | 工作线程完成通知，携带任务句柄 |
| `WM_APP_FRAME` | 采集线程通知有新帧（节流至 60Hz） |

**禁止跨线程 `SendMessage`**。工作线程一律 `PostMessage`。

### 3.4 DPI 与布局

- Manifest 声明 `PerMonitorV2`。
- 所有尺寸使用逻辑单位（96 DPI 基准），运行时 `scale = dpi / 96.0`。
- 布局函数 `layout(&mut self, client: Rect, dpi: u32)` 幂等，可重复调用。
- 字体按 DPI 创建缓存（`HFONT` 池）。

### 3.5 主题

| 部分 | 实现 |
|---|---|
| 标题栏 | `DwmSetWindowAttribute(DWMWA_USE_IMMERSIVE_DARK_MODE = 20)` |
| 菜单 | 同上（Win10 1809+） |
| 标准控件 | `uxtheme.dll` 序号 135/133 + `SetWindowTheme(..., L"DarkMode_Explorer")` |
| 自绘区 | 全部使用 `GetSysColor`，天然支持高对比度 |
| 圆角窗口 | Win11：`DWMWA_WINDOW_CORNER_PREFERENCE` |

深色模式依赖未公开导出，属尽力而为：启动时探测，失败则强制浅色并记录日志。

### 3.6 预览渲染

```
采集线程 ── 帧样本 ──▶ 帧槽（三元缓冲，只保留最新）
                              │
                              ▼
                    UI 线程：D3D11 纹理上传
                              │
                    ┌─────────┴──────────┐
                    ▼                    ▼
              DXGI Flip 呈现        D2D 叠加层
              (视频纹理)            (检测框/文字/网格)
```

- 优先请求 MF 输出 `RGB32`，由驱动/MF 完成 YUV→RGB。
- 降级顺序：`NV12` → 像素着色器转换；`MJPG` → 软件解码。
- 叠加层独立于视频层，参数调整只重绘叠加层。
- `Ctrl+滚轮` 缩放只改变变换矩阵，不重新解码。

## 4. 线程与并发模型

```
┌──────────────── UI 线程 ────────────────┐
│ Win32 消息循环 · 控件 · 布局 · D3D/D2D  │
│ 只做 <16ms 的工作                        │
└──────┬──────────────────────────────────┘
       │ PostMessage
┌──────▼───────────────┐   ┌──────────────────────────────┐
│ 采集线程 (MTA COM)    │   │ 工作线程池 (rayon)            │
│ SourceReader / Graph │   │ ├ 增强队列（并行，上限=核数）  │
│ 只负责取样本          │   │ ├ OCR 队列（串行，上限 1）     │
└──────┬───────────────┘   │ ├ 导出队列（串行，上限 1）     │
       │ 样本               │ └ 缩略图队列（并行，低优先级） │
       ▼                   └──────────────────────────────┘
┌──────────────────────┐
│ 解码线程（1–2）        │  MF 失败时才启用软件解码
└──────┬───────────────┘
       ▼
   帧槽 (latest-only)
```

规则：

1. **latest-only 帧槽**：预览永不排队，处理慢就丢帧，保证实时性。
2. **COM 线程亲和**：所有 COM 指针只在采集线程创建与释放。
3. **UI 线程零阻塞**：任何 >50ms 操作必须进工作队列，完成后 `PostMessage` 回 UI。
4. **取消传播**：任务句柄带 `AtomicBool` 取消标志，工作线程在每个阶段边界检查。
5. **优雅关闭**：先取消所有任务，再停采集，最后释放 D3D 设备。

## 7. 存储设计

### 7.1 目录布局

照片直接写入用户设置的输出根目录；设置、会话清单和回收站放在文档目录，
不污染照片目录。

```
<输出根>/
├─ 2026/11/07/扫描_20261107_143012_001.jpg
└─ 2026/11/07/扫描_20261107_143012_002.jpg

<文档>/usbscan/
├─ config.toml               # 设置
├─ session.json              # 会话清单（原子重写）
└─ trash/                    # 软件内删除的页面
```

### 7.2 原子写

```
fn atomic_write(path, bytes):
    tmp = path.with_extension("tmp.<pid>.<rand>")
    File::create_new(tmp) → write_all → flush → sync_all
    MoveFileExW(tmp, path, MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH)
```

- 拍摄成品采用 `CREATE_NEW` 直接占位（见 04 §7.2），不经过临时文件，避免重名竞态。
- 会话清单采用临时文件 + 替换，避免写一半。

### 7.3 会话持久化

- 每次页面变更后标记 `dirty`。
- 2 秒内若无新变更则落盘（尾沿防抖）。
- 退出时强制落盘。
- 清单里不记录原图，成品路径相对输出根保存。

### 7.4 启动与清空

1. 每次启动创建一个空会话，**不**读取上次的 `session.json`，左侧页面栏只显示
   本次新拍摄或导入的页面；磁盘上的旧照片保持原样。
2. 左侧页面栏的“清空”按钮只清空内存中的页面列表并保存空清单，不删除
   `<输出根>` 中的任何照片。
3. 软件内删除单页时，成品移到 `<文档>/usbscan/trash`，避免误删无法找回。

### 7.5 配置

```rust
pub struct Config {
    pub version: u32,
    pub general: GeneralConfig,
    pub capture: CaptureConfig,
    pub imaging: ImagingConfig,
    pub naming: NamingConfig,
    pub shortcuts: ShortcutConfig,
    pub ui: UiConfig,
}
```

- 位置：`<文档>\usbscan\config.toml`；便携模式为 `<exe>/data/config.toml`。
- 旧版本的 `%APPDATA%\usbscan\config.toml` 会在首次启动时迁移到文档目录。
- 加载失败：备份为 `config.bad.<时间>.toml`，使用默认值，提示用户。
- 版本迁移：`version` 字段驱动逐版升级函数。

## 8. 错误模型

### 8.1 分类

```rust
pub struct AppError {
    pub code: ErrorCode,          // 稳定错误码，用于日志与文档
    pub severity: Severity,       // Info | Warning | Error | Fatal
    pub message_key: &'static str,// i18n 键
    pub detail: Option<String>,   // 技术细节（仅日志）
    pub action: Option<Action>,   // 建议动作，如"重试""打开设备管理器"
}
```

### 8.2 错误码段

| 段 | 域 |
|---|---|
| `E1xxx` | 设备与采集 |
| `E2xxx` | 图像处理 |
| `E3xxx` | 存储与文件 |
| `E4xxx` | 命名规则 |
| `E5xxx` | OCR |
| `E6xxx` | 导出与打印 |
| `E9xxx` | 内部错误 |

### 8.3 呈现规则

| 严重性 | 呈现方式 |
|---|---|
| Info | 状态栏文本，3 秒淡出 |
| Warning | 状态栏黄点 + 可点击查看详情 |
| Error | 非模态提示条 + 操作按钮（不打断工作流） |
| Fatal | 原生 `TaskDialog`，必须用户确认 |

> 拍摄失败、写盘失败一律升级为 Error 并附操作按钮，不允许静默。

## 9. 日志与诊断

| 项 | 规格 |
|---|---|
| 库 | `tracing` + 自研滚动 writer |
| 位置 | `%LOCALAPPDATA%\usbscan\logs\usbscan-YYYYMMDD.log` |
| 保留 | 7 天 |
| 级别 | Info（默认）/ Debug（设置中开启） |
| 脱敏 | 默认不记录完整用户路径，仅记录文件名 |
| 结构 | `时间 级别 模块 消息 key=value` |
| 诊断包 | zip：日志、`config.toml`（脱敏）、设备枚举结果、系统信息、`dump` |

诊断包在导出前展示内容清单，由用户确认。

## 10. 决策记录（ADR）

| # | 决策 | 备选 | 理由 | 代价 |
|---|---|---|---|---|
| ADR-001 | 仅支持 Win10/11 | 兼容 Win7 | 可用现代 API、动态 CRT、简化采集栈 | 失去存量老旧机器 |
| ADR-002 | Media Foundation 为主 | DirectShow 为主 | 硬件解码、色彩转换、低 CPU、共享模式 | 杂牌驱动需兜底 |
| ADR-003 | Slint 声明式 UI（2026-11-08 替代 Win32 控件方案） | egui / WinUI3 / WebView | 圆角卡片与主题定制容易；UI 代码量低 | 引入 Slint 运行时；GPL-3.0 许可 |
| ADR-004 | 边拍边存 | 先存内存后导出 | 断电不丢、语义直观 | 需要命名规则在拍摄前确定；需处理撤销/回收 |
| ADR-005 | OCR 仅本地 Tesseract | 系统 OCR / 云 OCR | 离线承诺、可审计、无隐私风险 | 包体 +25MB，准确率依赖预处理 |
| ADR-006 | 开源发布 | 闭源商业授权 | 用户要求；便于审计与二开 | 无授权收入；需维护社区 |
| ADR-007 | 配方存参数不存像素 | 保存处理后位图 | 内存与磁盘友好、可随时重处理 | 重新处理需原图 |
| ADR-008 | 帧槽只保留最新帧 | 队列 | 保证预览实时，UI 卡顿不累积延迟 | 极慢机器会丢帧（可接受） |
| ADR-009 | 深色模式尽力而为 | 完全不做 | Win11 用户预期 | 依赖未公开 API，需优雅降级 |
| ADR-010 | 默认不联网、不检查更新 | 自动更新 | 隐私与开源信任 | 用户需手动检查 |

## 11. 代码规范

- `#![forbid(unsafe_op_in_unsafe_fn)]`，`usbscan-win` 与 `usbscan-capture` 允许 `unsafe`，其余 crate `#![deny(unsafe_code)]`。
- 每个 `unsafe` 块必须有 `// SAFETY:` 注释，说明前置条件。
- 错误一律用 `thiserror` 定义具体类型，禁止 `anyhow` 出现在库层（仅 app 层可用）。
- 生产路径禁止 `unwrap()` / `expect()`；用 `debug_assert!` 表达不变量。
- 单文件 ≤ 800 行，单函数 ≤ 60 行。
- 公共 API 必须有文档注释；私有函数加简短说明。
- 提交前必须 `cargo fmt` + `cargo clippy -- -D warnings`。

## 12. 测试策略

| 层次 | 方式 |
|---|---|
| 单元测试 | 命名引擎、配方序列化、色彩转换、几何变换 |
| 快照测试 | 图像算子：固定输入 → 输出 PNG 与基准比对（`insta`） |

| 手工测试 | 硬件矩阵（见 05 文档） |
| 性能测试 | 内建 `--bench-capture` / `--bench-imaging` 子命令 |
| 崩溃测试 | 拍摄中强制结束进程，验证恢复 |
