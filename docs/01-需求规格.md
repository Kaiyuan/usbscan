## 1. 产品定位

**一句话**：在 Windows 10/11 上，把任意 USB 摄像头当作文档扫描仪使用，拍摄即归档。

| 项 | 内容 |
|---|---|
| 产品名 | usbscan |
| 主程序 | `usbscan.exe` |
| 平台 | Windows 10 1607+ / Windows 11 |
| 架构 | x64（主）、ARM64（可选）、x86（可选） |
| 授权模式 | 开源，无授权限制 |
| 运行时依赖 | 无 |
| 网络行为 | 默认零联网，仅用户显式操作时访问 |

### 1.1 与"高拍仪厂商软件"的差异

现有高拍仪软件通常绑定自家硬件、捆绑广告、强制联网、界面陈旧。usbscan 的差异化：

1. **硬件无关**：只要是 UVC 摄像头就能用。
2. **拍摄即落盘**：不依赖"导出"动作，拍完文件就在磁盘上。
3. **可审计**：开源，无隐藏行为。
4. **原生手感**：与系统一致的窗口、控件、对话框、快捷键与无障碍支持。

### 1.2 设计原则

| 原则 | 落地要求 |
|---|---|
| 硬件宽容 | 任何 UVC 设备都能出图；不支持的能力隐藏而非报错 |
| 数据安全 | 快门即写盘；写盘失败必须显式告警，不允许静默丢弃 |
| 离线优先 | 断网状态下功能完整度 100% |
| 响应及时 | 任何操作 100ms 内有可见反馈 |
| 可解释 | 每个失败都有"原因 + 下一步动作" |
| 可维护 | 模块边界清晰，单文件不超过 800 行 |

## 2. 目标用户与典型场景

| 场景 | 用户 | 关键动作 | 特殊要求 |
|---|---|---|---|
| 政务窗口 | 窗口办事员 | 拍身份证/户口本 → 合成 → 归档 | 高吞吐、命名规则固定、批量 |
| 银行柜面 | 柜员 | 拍凭证 → 纠偏 → 上传/打印 | 稳定、不丢单、留痕 |
| 医院病案 | 病案室 | 批量拍 A4 纸张 | 连拍、自动翻页、去黑边 |
| 学校教务 | 教务老师 | 拍试卷/学籍表 → OCR | 中文识别准确率 |
| 企业档案 | 档案员 | 批量数字化、PDF/A 归档 | 大文档、可分页、可搜索 PDF |
| 个人 | 普通用户 | 拍票据、合同、快递单 | 零学习成本、默认可用 |

### 2.1 典型用户旅程

```
插入摄像头
   │
   ├─▶ 自动识别并打开预览（≤1.5s）
   │
   ├─▶ 首次使用：向导选择输出目录与命名规则（一次性）
   │
   ├─▶ 放上文档 → 自动检测边界 → 显示绿色框
   │
   ├─▶ 按 F9 拍照
   │      └─▶ 增强处理（≤250ms）→ 立即写入磁盘 → 缩略图出现
   │
   ├─▶ 连续拍 N 页
   │
   └─▶ 点击"导出 PDF" → 选择页码范围 → 生成单一 PDF（可选 OCR 文本层）
```

**边拍边存的数据契约**

一次拍摄产生以下文件：

```
<输出根>/
├─ 2026/11/07/扫描_20261107_143012_001.jpg      ← 成品（增强后，直接可用）
├─ 2026/11/07/扫描_20261107_143012_002.jpg
└─ .usbscan/
   ├─ session.json                                ← 会话清单（页面顺序、路径、配方、批注）
   ├─ raw/001.jpg                                 ← 原图（可关闭以节省空间）
   └─ thumbs/001.jpg                              ← 缩略图缓存
```

约束：

1. 成品文件一旦写出，**不因软件崩溃而损坏**（原子写保证）。
2. 用户在软件内删除页面时，同时删除成品、原图、缩略图与清单条目。
3. 用户在资源管理器中移动/删除文件后，软件下次启动扫描会话目录时应能识别"文件缺失"并提示。
4. 会话清单损坏时，可仅依靠磁盘上的图片文件重建会话（按修改时间排序、按命名规则解析序号）。

## 4. 非功能需求

### 4.1 性能

| 编号 | 指标 | 目标 | 上限 |
|---|---|---|---|
| NFR-P-01 | 冷启动到可预览 | ≤1.5 s | 2.5 s |
| NFR-P-02 | 1080p30 预览 CPU（4 核） | ≤8% | 15% |
| NFR-P-03 | 4K30 MJPEG 预览 CPU | ≤25% | 40% |
| NFR-P-04 | 快门到文件落盘完成 | ≤250 ms | 500 ms |
| NFR-P-05 | 1200 万像素全量增强 | ≤350 ms | 800 ms |
| NFR-P-06 | OCR A4 300dpi 中文 | ≤2.5 s | 4 s |
| NFR-P-07 | 内存（10 页未导出） | ≤350 MB | 700 MB |
| NFR-P-08 | 界面输入响应 | ≤50 ms | 100 ms |
| NFR-P-09 | 连续拍摄 100 页无丢帧、无重名 | 100% | — |

### 4.2 可靠性

- 写入磁盘采用原子替换，任何时刻断电不会产生半截文件。
- 单次拍摄失败不影响后续拍摄。
- 采集线程异常退出后，UI 仍可操作并可重建流。
- 会话清单每 2 秒内自动持久化，崩溃最多丢失最近 2 秒的页面索引（图片文件本身已落盘）。

### 4.3 可用性与无障碍

- 全部功能可用键盘完成。
- 支持高对比度主题（所有自绘部分使用系统颜色）。
- 原生控件自动获得屏幕阅读器支持；自绘预览区补充 UI Automation 通知。
- 界面文字随系统 DPI 缩放，125%/150%/200% 下无错位。

### 4.4 可维护性

- 模块间只通过公开接口通信，禁止跨 crate 访问内部类型。
- 所有 `unsafe` 代码必须附安全性说明与单元测试。
- CI 强制 `fmt` + `clippy -D warnings` + 测试通过。

### 4.5 隐私

- 默认不收集任何数据。
- 无自动网络请求（含更新检查，默认手动）。
- 日志不记录图像内容、不记录用户文件全路径（可配置）。
- 诊断包导出前显示内容清单，由用户确认。

## 5. 范围外（v1 不做）

| 项 | 原因 |
|---|---|
| Windows 7 / 8 支持 | 已确认放弃 |
| TWAIN / WIA 平板扫描仪 | 无视频流，架构不同，留待后续 |
| 云端 OCR / 云存储 | 与离线定位冲突 |
| 手机端 / Web 端 | 非目标平台 |
| 视频编辑（剪辑、转码） | 只做录制，不做后期 |
| 多用户/账户体系 | 单机软件 |
| 授权、试用、激活 | 开源项目 |
| 自动上传到业务系统 | 由用户用命令行或系统集成解决 |

## 6. 验收标准

### 6.1 功能验收

1. 在干净安装的 Windows 10 21H2 与 Windows 11 23H2 上，安装包可正常安装、卸载无残留。
2. 至少 6 类摄像头（见 05 文档测试矩阵）均能出图。
3. 拔插摄像头 20 次，软件均能自动恢复预览。
4. 连续拍摄 100 页，磁盘上文件数与序号连续，无重名、无 0 字节文件。
